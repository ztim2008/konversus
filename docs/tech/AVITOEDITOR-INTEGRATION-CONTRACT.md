# AVITOEDITOR INTEGRATION CONTRACT

Короткий контракт интеграции подпроекта `avitoeditor` с core-платформой AVITO CONVERSION BUILDER.

## 1. Роль сервиса

`avitoeditor` — отдельный сервис визуального улучшения объявлений.

Он отвечает не за аудит как таковой, а за следующий шаг после аудита:
- собрать улучшенную визуальную версию;
- сделать инфографику или карточку;
- сохранить проект;
- экспортировать финальный визуал для публикации.

В продуктовой цепочке это модуль слоя Improvement Workspace.

## 2. Что core-платформа может передавать в avitoeditor

Минимальный входной контракт:
- `listing_id` — идентификатор объявления в core;
- `title` — заголовок объявления;
- `category` — категория;
- `images[]` — исходные изображения;
- `audit_findings[]` — выводы аудита по фото и инфографике;
- `recommendations[]` — приоритетные визуальные правки;
- `brand_context` — опционально стили, цвета, акценты.

## 3. Что avitoeditor должен возвращать в core

Минимальный выходной контракт:
- `project_id` — идентификатор проекта редактора;
- `listing_id` — связь с объявлением в core;
- `exported_images[]` — финальные изображения;
- `template_id` — если использован шаблон;
- `updated_at` — время последнего изменения;
- `status` — draft/exported/applied.

## 4. Первый практический способ интеграции

Самый простой стартовый сценарий:
1. Пользователь открывает аудит объявления в core-платформе.
2. Нажимает CTA вроде «Исправить визуал».
3. Core открывает `avitoeditor` по deep-link.
4. В deep-link передаются `listing_id`, шаблон или базовые данные для старта.
5. После экспорта редактор возвращает ссылку на итоговый визуал или payload в core.

На первом этапе этого достаточно даже без полной общей авторизации.

## 5. Целевая интеграция

Позже интеграция должна дорасти до следующей модели:
- единая авторизация или доверенный session flow;
- загрузка изображений и проектов через общий API;
- хранение связи «объявление → проект редактора → итоговый экспорт»;
- запуск редактора прямо из кабинета без ручного копирования данных.

## 6. Что не делаем на первом этапе

Не усложняем старт:
- без полного merge кода avitoeditor в core;
- без немедленного переноса всего UI в кабинет;
- без обязательного единого monolith-flow на первом шаге.

Сначала нужен рабочий bridge, а не идеальная архитектура.

## 7. Текущий статус

- `avitoeditor` считается отдельным сервисным подпроектом;
- начата его санация для безопасного git-контура;
- прямой integration bridge в core пока не реализован;
- этот документ фиксирует минимальный контракт, по которому можно делать первую интеграционную задачу.
