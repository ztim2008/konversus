# Схема Block Library

## Зачем нужен этот документ

Этот документ фиксирует не просто список UI-компонентов, а систему смысловых blocks для proposal builder.

Каждый block в этом проекте — это не декоративный модуль страницы, а единица B2B digital storytelling.

Каждый block отвечает сразу за несколько задач:

- смысл,
- этап продажи,
- усиление доверия,
- аргументацию,
- визуальную упаковку,
- UX storytelling.

Builder должен собирать не страницу как набор секций, а digital pitch для B2B-компании.

## Основные принципы block system

1. Каждый block продает.
2. Каждый block усиливает доверие.
3. Каждый block должен выглядеть дорого.
4. Каждый block должен быть презентационным.
5. Каждый block должен быть пригоден для share-page, PDF и mobile.
6. Каждый block должен иметь `visual mode`, `compact mode` и `PDF mode`.

## Главная рамка

Block system должен быть не визуальным конструктором ради конструктора.

Он должен быть системой сборки B2B digital storytelling.

Это означает:

- блоки должны помогать строить narrative flow,
- библиотека блоков должна группироваться по смысловым категориям,
- блоки должны быть пригодны для разных форматов вывода,
- визуальная логика block library должна работать как presentation system.

## Структура block library

На системном уровне библиотека блоков делится на такие категории:

1. `hero-blocks`
2. `audit-blocks`
3. `problem-blocks`
4. `seo-blocks`
5. `trust-blocks`
6. `product-blocks`
7. `media-blocks`
8. `ai-enhanced-blocks`
9. `strategy-blocks`
10. `cta-blocks`
11. `process-blocks`
12. `industrial-blocks`
13. `analytics-blocks`
14. `contact-blocks`

Ниже фиксируется рабочая логика каждой категории.

## 1. Hero Blocks

Главная задача категории — создать ощущение:

`это новый уровень компании`.

### 1.1 Cinematic Hero

Состав:

- большой заголовок,
- industrial background,
- CTA,
- motion,
- overlay,
- metrics.

Использование:

- главный opening block,
- основной emotional framing концепта.

### 1.2 Split Hero

Левая часть:

- проблема.

Правая часть:

- новый digital vision.

Использование:

- сильный opening для audit-oriented proposal,
- хороший мост между pain reveal и новым образом компании.

### 1.3 Video Hero

Background video:

- производство,
- оборудование,
- timelapse,
- cinematic footage.

Использование:

- для компаний, где видео сразу усиливает ощущение масштаба и технологичности.

## 2. Audit Blocks

Это одна из самых важных категорий.

Именно audit blocks дают pain reveal и обосновывают, почему новый digital-концепт нужен не “ради красоты”, а ради продаж и доверия.

### 2.1 Website Audit

Показывает:

- слабые места сайта,
- устаревший дизайн,
- проблемы UX,
- mobile issues,
- SEO issues.

Предпочтительная подача:

- визуальные карточки,
- severity indicators,
- краткие комментарии.

### 2.2 Video Audit Block

Поддерживает:

- Loom,
- YouTube,
- MP4.

Нужен состав:

- preview cover,
- play overlay,
- краткое описание аудита.

### 2.3 Competitor Gap

Сравнивает:

- клиента,
- конкурентов.

Параметры сравнения:

- дизайн,
- SEO,
- доверие,
- mobile,
- скорость,
- структура.

## 3. Problem Blocks

Эта категория фиксирует проблемы, которые мешают продаже и снижают доверие.

### 3.1 Trust Problems

Показывает проблемы вида:

- сайт выглядит старым,
- нет ощущения масштаба,
- слабая визуальная подача,
- сайт не вызывает доверия.

### 3.2 Lead Generation Problems

Показывает проблемы вида:

- нет CTA,
- нет конверсии,
- нет сценариев захвата,
- нет четкой точки следующего шага.

### 3.3 Mobile Experience Problems

Показывает:

- неудобный mobile,
- перегруженность,
- слабую адаптацию,
- плохую читаемость.

## 4. SEO Blocks

Для B2B эта категория критически важна, потому что сайт должен не только выглядеть дорого, но и расти через поисковый спрос.

### 4.1 SEO Audit

Показывает:

- слабую структуру,
- отсутствие посадочных,
- отсутствие кластеров,
- плохие title/meta,
- отсутствие SEO-архитектуры.

### 4.2 SEO Growth Map

Показывает, как сайт может расти:

- категории,
- подкатегории,
- страницы продукции,
- статьи,
- кейсы,
- гео-страницы.

### 4.3 Search Demand Block

Показывает спрос по нише.

Примеры:

- металлообработка,
- лазерная резка,
- промышленное оборудование.

## 5. Trust Blocks

Эта категория усиливает доверие и помогает компании выглядеть крупнее, стабильнее и серьезнее.

### 5.1 Company Metrics

Метрики:

- лет на рынке,
- сотрудников,
- объектов,
- клиентов,
- регионов.

### 5.2 Certificates Block

Показывает:

- ISO,
- лицензии,
- документы,
- стандарты.

### 5.3 Clients & Partners

Показывает логотипы:

- партнеров,
- клиентов,
- поставщиков.

### 5.4 Geography Block

Показывает:

- карту,
- регионы,
- поставки,
- производство.

## 6. Product Blocks

Эта категория нужна, когда предложение должно показать не только образ компании, но и сам продуктовый ассортимент или производственные возможности.

### 6.1 Product Grid

Показывает:

- карточки продукции,
- базовую сетку предложений,
- быстрый обзор ассортимента.

### 6.2 Product Showcase

Показывает:

- один или несколько ключевых продуктов,
- premium visual presentation,
- акцент на качестве и деталях.

### 6.3 Equipment Block

Показывает:

- оборудование,
- мощности,
- технологии.

## 7. Media Blocks

Это ключевая категория, потому что в производственном B2B визуал часто усиливает ценность концепта сильнее текста.

### 7.1 Industrial Gallery

Сетка фото:

- производство,
- цеха,
- оборудование,
- детали процесса.

### 7.2 Before / After

Слайдер или paired comparison:

- старый визуал,
- новый visual concept.

### 7.3 Cinematic Media Block

Показывает:

- большое fullscreen media,
- эмоциональный визуальный акцент,
- дорогую презентационную паузу в документе.

### 7.4 Video Presentation

Встроенное видео:

- презентация,
- аудиторский разбор,
- ролик производства,
- объяснение стратегии.

## 8. AI Enhanced Blocks

Эта категория фиксирует не просто AI-вспомогательные действия, а блоки, где AI-результат сам становится частью pitch.

### 8.1 AI Visual Enhancement

Показывает:

- old image,
- AI enhanced image,
- визуальную разницу между текущим и усиленным состоянием.

### 8.2 AI Copywriting Block

Показывает AI-generated слой:

- positioning,
- offer,
- industrial messaging.

Важно:

- AI output не должен выглядеть как generic text,
- он должен поддерживать premium industrial tone.

## 9. Strategy Blocks

Эта категория объясняет, что именно изменится после redesign и как новый digital будет работать на бизнес.

### 9.1 Digital Transformation

Показывает:

- что изменится после redesign,
- как усилится образ компании,
- как изменится подача бренда.

### 9.2 Lead Strategy

Показывает, как сайт будет:

- привлекать,
- конвертировать,
- удерживать.

### 9.3 SEO Strategy

Roadmap:

- SEO architecture,
- landing pages,
- content structure.

### 9.4 B2B Positioning

Показывает, как компания будет выглядеть:

- крупнее,
- современнее,
- технологичнее.

- масштабы.

### 12.2 Technology Block

Показывает:

### 12.3 Quality Control Block

Показывает:

## 13. Analytics Blocks

Эта категория нужна для рационального обоснования digital-модернизации.

### 13.1 Performance Block

### 14.1 Founder Block

Закрывающий block:

## Обязательные metadata для blocks

Каждый block в библиотеке должен иметь catalog-level metadata:

- `id`
- `type`
- `title`
- `description`
- `category`
- `icon`
- `preview_image`
- `tags`
- `schema`
- `variants`
- `dark_mode_support`
- `pdf_support`
- `mobile_support`
- `animations`

Эти metadata нужны не только для хранения, но и для product experience:

- visual catalog слева,
- templates,
- quick insert,
- рекомендации по сценарию,
- preview карточки,
- будущая фильтрация block library.

## Режимы рендера blocks

Каждый block должен поддерживать три режима:

### 1. Visual Mode

Основной режим для share-page и live preview.

Требования:

- дорогая визуальная подача,
- motion,
- depth,
- visual hierarchy,
- презентационный характер.

### 2. Compact Mode

Используется внутри builder там, где нужен быстрый обзор структуры или облегченный preview.

Требования:

- меньше высота,
- короче тексты,
- упрощенная media подача,
- быстрый скан документа.

### 3. PDF Mode

Используется для экспорта.

Требования:

- стабильная печатная верстка,
- предсказуемые отступы,
- корректная типографика,
- статичная адаптация без сложной анимации.

## Продуктовый вывод

Система blocks в Factory Proposal Builder должна работать не как page builder, а как presentation engine для B2B digital pitch.

Именно поэтому block library должна проектироваться одновременно как:

- narrative system,
- trust system,
- visual system,
- sales system.

Если это удержать, builder будет ощущаться не как редактор, а как luxury workspace для digital strategist.
