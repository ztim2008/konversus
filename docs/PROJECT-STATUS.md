## Что уже работает в production

### Инфраструктура

- Next.js 16.2.6 (Turbopack), App Router, `"use client"` только для интерактива
- MySQL (`factory_proposal_builder`), хост `127.0.0.1`, пул через `getDbPool()`
- PM2 процесс `konversus-fpb` (id=4), деплой: `npm run build && pm2 restart konversus-fpb --update-env`
- Домен `konversus.ru`, Nginx reverse proxy

### Авторизация

- single-owner вход (`/auth`), закрытый кабинет (`/dashboard`)
- все server actions защищены `requireCurrentAdmin()` из `src/lib/auth/session.ts`

### Бизнес-сущности

- компании: создание, редактирование, **удаление** (каскадное)
- концепты: создание, редактирование в builder, **удаление**
- share-links: публикация, уникальные просмотры, device tracking (mobile/desktop)
- фидбек: форма на share-странице, просмотр в `/dashboard/reviews`

### Builder

- editor route `/dashboard/proposals/[proposalId]`
- структура документа — JSON в `proposal.structure`
- каталог блоков: Hero, факты, текст+фото, галерея, видео, HTML, CTA
- palette switcher, publish/update share-link
- PDF экспорт через `/share/[slug]/pdf`

### Share-страница (`/share/[slug]`)

- публичная, без авторизации
- кинематографичный **intro-занавес** (монограмма → прогресс → уход)
- **scroll-reveal** для блоков контента
- **exit-intent модал** с фото автора и контактами (1 раз за сессию)
- badge «Студия КОНВЕРСУС» в топбаре + **подвал** со ссылкой на konversus.ru
- форма фидбека

### Главная страница (`/`)

- все тексты (H1, подзаголовок, биография, контакты) управляются через настройки
- портфолио: случайные изображения из `/portfolio/`

### 404 страница

- `src/app/not-found.tsx`, кинематографичный dark-дизайн
- `robots: noindex`

### Настройки сайта (`/dashboard/settings`)

Полный CMS-редактор без деплоя. Данные в таблице `site_settings` (key-value).

**Что редактируется:**
- тексты главной: hero badge, H1, подзаголовок, кнопки, биография, контакты
- SEO: title, description, keywords, OG image
- аналитика: Яндекс.Метрика ID, Google Analytics ID, Яндекс.Вебмастер key
- **сквозная вставка кода**: произвольный HTML/`<script>` код работает на всех страницах

**Как работает вставка кода:**
- код сохраняется в `site_settings.body_scripts`
- `BodyScriptInjector` (`src/components/body-script-injector.tsx`) — `"use client"` компонент в `layout.tsx`
- скрипты создаются через `document.createElement("script")` → исполняются браузером
- работает на главной, дашборде, share-страницах, лендингах — везде
- деплой **не нужен**, применяется сразу после сохранения

## Технические решения и ошибки, которых нужно избегать

### 1. Ошибки с HTML и гидрацией
- Никогда не вставляйте пользовательский HTML через `dangerouslySetInnerHTML` в SSR-компонентах — это приводит к ошибке #418 (hydration mismatch).
- Всегда используйте `ClientHtmlBlock` для вывода HTML (Tiptap, Custom HTML).

### 2. Inline-стили и адаптивность
- Не используйте inline-стили для размеров шрифтов — они ломают медиазапросы и адаптивную типографику.
- Все размеры и цвета должны идти через CSS custom properties и медиазапросы в `globals.css`.

### 3. Exit-intent modal и JS-интерактив
- Модальное окно реализовано через IIFE и sessionStorage, чтобы не мешать SSR и не вызывать конфликтов с React.
- Все JS-слушатели должны быть изолированы и не влиять на остальной код страницы.

### 4. Добавление новых блоков
- Следуйте [BLOCK-AUTHORING-GUIDE.md](BLOCK-AUTHORING-GUIDE.md) — только строго по шагам.
- Дублируйте CSS для SSR/canvas и публичной страницы.
- Используйте функцию `blockColorVars` для токенов цвета.
