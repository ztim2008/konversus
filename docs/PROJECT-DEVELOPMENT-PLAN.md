План развития AVITO CONVERSION BUILDER с едиными статусами задач.

## Легенда статусов
- 🔴 Запланировано
- 🔵 В работе
- 🟢 Сделано

## Этапы и статусы

| Этап | Статус | Цель | Что входит |

| Foundation | 🟢 Сделано | Подготовить чистую базу проекта | Удаление WordPress, базовая документация, каркас монорепо, стартовая страница |

## Правила работы с блокерами
1. Если блокер > 3 рабочих дней, задача не остается в «🔵 В работе», а переводится в «🔴 Запланировано» с комментарием причины.
2. Каждый блокер обязан иметь owner, дедлайн и следующий конкретный шаг.
3. На weekly review сначала закрываем блокеры core value loop, потом второстепенные задачи.

## Технологические правила проекта
1. Ведем проект только на русском языке: документация, названия задач, термины в процессе.
2. Для России: минимизируем количество сторонних зависимостей и внешних сервисов.
3. Иконки используем локально (lucide или аналог), без подключения с CDN.
4. Скрипты и вспомогательные инструменты по возможности храним локально в проекте.

## Definition of Done (для каждой задачи)
- Есть рабочая реализация и проверка ключевого сценария.
- Обновлены docs и CHANGELOG.
- Добавлен rollback-safe путь (если изменение затрагивает данные или деплой).

## Как ведем проект (мой подход)
1. Один активный фокус на спринт: не распыляемся, закрываем core value loop.
2. Каждую неделю обновляем только статусы и короткий результат по этапам.
3. Любая новая крупная идея сначала в backlog, не ломаем текущий спринт.
4. Приоритет всегда по ROI: то, что быстрее покажет пользователю +лиды/+конверсию.
5. Релизы маленькими порциями: проще откатить и проще диагностировать.

## Ритуал обновления плана
1. В начале недели: что переводим в 🔵.
2. В конце недели: что переводим в 🟢 и что блокирует 🔴.
3. Раз в месяц: пересборка приоритетов по данным (не по ощущениям).
