# Подключение локальной базы

## Зачем нужен этот документ

Здесь собран прямой путь для запуска реального backend-контура на вашем сервере:

1. подключить локальную MySQL-базу,
2. накатить SQL-схему MVP,
3. заполнить `.env.local`,
4. войти под владельцем,
5. проверить dashboard.

Текущая модель проекта:

- один владелец,
- один админ,
- без ролей,
- без командного режима,
- без внешнего auth-провайдера.

## Шаг 1. Подготовить `.env.local`

Создайте или обновите `.env.local` в корне проекта на основе `.env.example`.

Минимальные переменные:

```env
DB_HOST=127.0.0.1
DB_PORT=3306
DB_NAME=factory_proposal_builder
DB_USER=root
DB_PASSWORD=
ADMIN_EMAIL=bilariuss@yandex.ru
ADMIN_PASSWORD=
AUTH_SECRET=
```

Важно:

- `DB_PASSWORD` и `AUTH_SECRET` нельзя коммитить в git,
- пароль владельца хранится только локально в `.env.local`,
- `AUTH_SECRET` должен быть длинной случайной строкой.

## Шаг 2. Создать базу данных

Если база еще не создана, создайте ее на сервере или в панели хостинга.

Рекомендуемое имя:

- `factory_proposal_builder`

Кодировка:

- `utf8mb4`

## Шаг 3. Накатить схему MVP

Подключитесь к MySQL и выполните SQL из файла:

- `sql/001_mvp_core_mysql.sql`

После этого в базе появятся:

- `companies`,
- `proposals`,
- `assets`,
- `share_links`.

## Шаг 4. Заполнить владельца

В `.env.local` задайте:

- `ADMIN_EMAIL`
- `ADMIN_PASSWORD`
- `AUTH_SECRET`

Для вашего сценария регистрация не нужна. Владелец задается напрямую через локальные переменные окружения.

## Шаг 5. Проверить вход

Запустите проект:

```bash
npm run dev
```

Дальше проверьте сценарий:

1. открыть `/auth`,
2. войти под владельцем,
3. перейти в `/dashboard`,
4. создать первую компанию,
5. создать первый концепт.

## Что делать дальше

После подтверждения локального входа и dashboard можно переходить к следующему слою:

1. экран компании,
2. экран концепта,
3. create concept flow,
4. share-page,
5. PDF pipeline.
