## Задача A — прогон и баг-лист

Сделай smoke / полубоевой прогон и запиши в `docs/devlog/2026-09.md` секцию **«Прогон + недостатки»**.

Минимум проверок:

1. `POST /api/lead-radar/nightly-run` (auth `LEAD_RADAR_CRON_SECRET`) — limit небольшой или dry-run по ситуации; на проде не спамить клиентов.  
2. Очередь «Сегодня»: скрин, email, plain КП в превью, Отправить (лучше testMode сначала) / Пропустить.  
3. Telegram группа: утро (план+фото+текст КП), ✅ отправлено, 🔥 ответ, вечерний отчёт (если sent>0).  
4. Вкладка «Статистика»: цифры дня = `collectDayFacts` / вечерний TG.  
5. CTA `/api/lead-radar/interest?lead=` и webhook reply (идемпотентность).  
6. `npm run harness:check`.

Для каждого недостатка: **симптом → где в коде → критичность (P0/P1/P2) → предложение**.  
Не выдумывай — если нет данных, пиши `[уточнить: …]`.

Уже известный P1 от владельца: **настройки радаров / ниш слишком узкие**.

## Задача B — анализ логистики ниш (жирные клиенты)

Нужен **анализ + план**, не сразу большой рефактор.

### Вопрос владельца

Интересуют жирные клиенты: **стройка, ремонт, услуги, производство**.  
Текущая «рулетка» городов/ниш кажется узкой. Хочется продумать логистику (возможно рулетку сегментов / вертикалей).

### Что исследовать в коде

- `day-picker.ts` — как выбираются city+niche, cooldown, bootstrap.  
- `lead-radar-geo.ts` — города, travel flags.  
- Serper query builder — какие запросы уходят в SERP.  
- Фильтр компаний — не режет ли полезных подрядчиков.  
- Админка «Радары» vs Auto nightly — два контура? Как стыкуются?

### Выход артефакта

Создай/обнови документ плана, например:

`docs/plans/2026-09-lead-radar-niche-roulette.md`

Структура:

1. **Как сейчас** (1 экран: поток выбора дня).  
2. **Боли** (из прогона + узкие ниши).  
3. **Целевой ICP** — жирный клиент: критерии (бюджет сайта? размер штата? B2B?). `[уточнить]` где нужно.  
4. **Варианты рулетки** (сравнить 2–3):  
   - A: город × ниша как сейчас, расширенный словарь ниш;  
   - B: «вертикаль» (стройка / ремонт / услуги / производство) → подниши → город;  
   - C: рулетка weighted по hotScore/ответам/марже;  
   - плюсы/минусы/объём работ.  
5. **Словарь ниш v2** (черновик RU) под 4 вертикали — 8–15 запросов на вертикаль, пригодных для SERP «сайт компании».  
6. **DoD следующей итерации** (маленький инкремент, не «переписать всё»).  
7. **Вопросы владельцу** (короткий список).

После плана — **стоп и согласование**, код ниш не пихать без «делаем вариант X».
