# План: день как поток · лимит 40 писем

**Дата:** 2026-09-14

**Вход владельца (уточнение):** 40 клиентов собрать · **автоотправка без кнопки** · как контент-цех · делать сразу.

---

## 1. AS-IS (после теста)

```
Ночь/утро  → одна пачка queued ≤20 (настраивается в Рулетке)
День       → человек: Send / Skip / ручной URL
Вечер      → факт в TG (если sent>0)
```

| Что работает | Боль |
|--------------|------|
| Качество КП / тон Игоря | Пачка 20 — мало для дня |
| Ручной Send держит репутацию SMTP | Всё приходит утром → либо шквал, либо простой |
| Skip/TG/статистика | «Отвечать самому» неудобно (см. §4) |
| Рулетка + ручной URL | Нет добора днём |

**Два разных лимита (важно развести):**

| Лимит | Сейчас | Запрос |
|-------|--------|--------|
| **Очередь** `queued` (заготовки) | ~20 | может быть ≥40 (буфер) |
| **Отправка** `sent` за календарный день | фактически ≤ разбора человеком | **жёстко 40** |

Поток = не «собрать 40 утром», а **кормить очередь волнами** и **тратить бюджет отправки равномерно**.

---

## 2. Коммерция (гипотезы)

Письма «хорошо поставлены» → узкое место не копирайт, а **пропускная способность дня** и **скорость реакции на ответы**.

| Метрика | Пачка 20 | Поток 40 sent |
|---------|----------|----------------|
| Потенциал replied (при той же open/reply rate) | ×1 | ~×2 |
| Стоимость AI/SERP/скрин на sent | выше, если много skip | ниже при лучшем доборе |
| Риск SMTP | пик утром | ниже при равномерной отправке |
| Внимание оператора | один залп | несколько коротких сессий / полуавто |

Риски ×2 объёма: жалобы, прогрев ящика, качество SERP при частых запросах. Смягчение: **кап sent=40**, волны поиска, не взрывать SMTP.

## 3. TO-BE — рекомендуемый вариант: «волны + бюджет 40»

### Формула дня (новая)

```
УТРО     = план + первая волна (~10–15 в очередь) + TG
ДЕНЬ     = доборы по расписанию + разбор/отправка с бюджетом 40
ВЕЧЕР    = факт (sent/opened/replied) + остаток очереди
```

### Расписание (черновик, МСК)

| Время | Авто | Человек |
|-------|------|---------|
| 06:00 | Волна 1: добрать очередь до буфера (напр. 15–20 queued) | — |
| 09–12 | — | Send из «Сегодня», темп ~8–12 |
| 12:00 | Волна 2: добрать, если queued < порога | — |
| 13–17 | — | Send, темп ~8–12 |
| 17:00 | Волна 3: добор под вечерний остаток бюджета | — |
| 17–19 | — | добить бюджет до 40 |
| 21:00 | Daily-report | — |

**Бюджет отправки:** `sent_today < 40` — жёсткий стоп в `sendQueuedLead` + счётчик в шапке «Сегодня» (`отправлено 12/40`).  
**Буфер очереди:** отдельно, напр. `queued` cap 25–50 (чтобы волны не забивали экран); в Рулетке два поля: «лимит отправки/день» и «макс. в очереди».

### Что остаётся ручным / что можно автоматизировать

| Действие | Сейчас | В потоке v1 |
|----------|--------|-------------|
| Поиск + email + скрин + КП | авто ночью | авто волнами |
| **Отправка письма** | кнопка человека | **кнопка** (инвариант) |
| Skip | человек | человек (+ позже TG inline) |
| Ответ клиенту на входящее | вы сами | см. §4 |

### Альтернативы (если отвергнете волны)

| Вариант | Суть | Минус |
|---------|------|-------|
| B. Утро×40 одной пачкой | Проще код | Шквал разбора, хуже SMTP |
| C. Continuous cron каждые 30–60 мин | Макс. «поток» | Сложнее квоты Serper/токены, шум TG |

**Рекомендация:** волны (A), не B и не полный continuous сразу.

## 4. «Отвечать самому неудобно»

Это **отдельный трек** от лимита 40. Уточнить, что именно болит:

| Боль | Смысл | Направление |
|------|--------|-------------|
| P-reply | Клиент ответил / кликнул — надо писать вручную | Шаблоны ответа Игоря · TG «🔥 + черновик ответа» · позже IMAP/бот |
| P-send | Жалко время на кнопку Send по каждому | TG inline Send (бэклог) · или полуавто «отправить следующие N» с подтверждением |
| P-partner | Хотите, чтобы отвечал напарник | Роли в TG · чеклист · доступ в админку |

Пока в плане потока **не снимаем** human-in-the-loop на первую отправку. Автоответчики клиенту — только после явного ОК.
