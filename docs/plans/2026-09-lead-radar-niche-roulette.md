## 0. Две задачи (приоритет)

| # | Задача | Зачем | Когда делать |

| 1 | **Логистика / рулетка** городов × вертикалей | Утро само собирает «жирных», не одни и те же 4 ниши | Согласовать модель → маленький инкремент словаря |

## 1. Как сейчас (один экран)

```
УТРО (cron 06:00)
  day-picker → 1 город + 1 ниша из NICHES_V1 (всего 4 строки)
  → Serper «{ниша} {город}»
  → фильтр компаний → audit → email → скрин → КП
  → queued ≤20 → TG дайджест

ДЕНЬ
  админка «Сегодня»: Отправить / Пропустить (человек)
  вкладка «Радары» = ДРУГОЙ контур (Maps/ручной поиск),
  не крутит Auto nightly

ВЕЧЕР (21:00)
  факт дня в TG (если sent>0)
```

**Словарь Auto сейчас:**  
города: СПб, Москва, Омск, В. Новгород · ниши: ремонт квартир / строительная компания / стройматериалы / инженерные сети  
bootstrap: 14 дней только СПб · cooldown города: 3 дня

**Боль:** 4 ниши × 4 города = узкая рулетка; «услуги» и «производство» почти не представлены; вкладка «Радары» путает (широкие подсказки), но Auto их не использует.

## 3. Как «показать» рулетку человеку (не специалисту)

Три формата — можно совместить:

### А) Таблица «календарь на 2 недели» (рекомендую как главный)

Строки = дни, столбцы = город / вертикаль / запрос / зачем.

Пример:

| День | Город | Вертикаль | Запрос в Google | Заметка |
|------|-------|-----------|-----------------|--------|
| Пн | СПб | Ремонт | ремонт квартир под ключ Санкт-Петербург | hot |
| Вт | Омск | Стройка | строительная компания Омск | travel |
| … | … | … | … | … |

Плюс: видно «что будет утром». Минус: надо один раз заполнить словарь.

### Б) «Колесо» / слоты в чате (Telegram)

Каждое утро бот уже пишет: `Пачка · город · ниша`.  
Дополнить: `Вертикаль: Ремонт · слот 3/12 · следующий: Производство / СПб`.

Плюс: привычный канал. Минус: нельзя править будущее без админки.

### В) Вкладка «Рулетка» в админке

Список слотов + кнопка «сегодня принудительно: город+ниша» + превью ближайших 7 дней.

Плюс: контроль. Минус: чуть больше UI.

**Идея на старт:** таблица в docs (этот файл) + утренний TG уже показывает факт слота. Вкладку «Рулетка» — позже, если не хватает.

## 4. Варианты рулетки (выбрать один)

### A — как сейчас, но толстый словарь

`город × ниша`, ниш станет 30–50 вместо 4.  
Ротация: cooldown города + round-robin / shuffle ниш.

| + | − | Объём |
|---|---|--------|
| Минимум кода (`NICHES_V1` → массив) | Нет группировки «стройка vs услуги» | S (0.5–1 день) |
| Быстро проверить SERP | Легко снова уехать в «тонкие» запросы | |

### B — вертикаль → подниша → город ⭐ рекомендую

Сначала крутим **вертикаль** (стройка / ремонт / услуги / производство),  
внутри — подниша (запрос), потом город с cooldown.

| + | − | Объём |
|---|---|--------|
| Понятно владельцу («сегодня стройка») | Чуть больше модели данных | M (1–2 дня) |
| Баланс 4 жирных сегментов | Нужен словарь v2 | |
| Легко весами: 40% стройка, 30% ремонт… | | |

### C — weighted по ответам / hotScore

Как B, но веса слотов растут от `replied` / открытий / ручных 🔥.

| + | − | Объём |
|---|---|--------|
| Учится на факте | Мало данных первые недели → шум | L (после 2–3 недель факта) |
| | Сложнее объяснить «почему сегодня это» | |

**Предложение:** внедрить **B** со словарём v2; через 2–3 недели оценить C.  
Если нужно «вчера было узко — сегодня шире» за вечер — временно **A** с куском словаря B.

## 6. Задача 2 — ручной URL в очередь

### Что хочет клиент (продукт)

Вставил ссылку сайта → система сама: аудит, email, скрин, КП → лид в **«Сегодня»** (как ночные), можно Отправить/Пропустить.  
Опционально: пуш в TG «ручной лид».

### Что уже есть (не путать)

| Кусок | Умеет | Не умеет |
|-------|--------|----------|
| `enrich-site` | audit + email + скрин | не создаёт queued + КП пачкой |
| `queue-site` | статус → queued | не проверяет email/скрин/КП |
| вкладка «Радары» | поиск по городу/нише | не «одна ссылка → очередь» |
| «Сегодня» | send/skip | нет поля «добавить URL» |

### UX (простой)

На вкладке **«Сегодня»** сверху:

```
[+ Добавить сайт]  https://example.ru          [В очередь]
```

Поток:

1. Нормализация URL (добавить https при необходимости).  
2. Дедуп по domain (если уже queued/contacted сегодня — сказать).  
3. Тот же пайплайн, что nightly на 1 сайт: filter не нужен (человек уже выбрал) → enrich → KP → `queued`.  
4. Лимит 20: если пачка полная — либо отказ с текстом, либо «сверх лимита с подтверждением» `[уточнить]`.  
5. Источник: `source=manual_url`.  
6. TG: короткое «➕ Ручной лид: domain» + скрин (уже с multipart-фиксом).

### DoD инкремента (маленький)

- [ ] Поле URL на «Сегодня»  
- [ ] API `enqueue-url` (или action): один сайт → queued с email+скрин+КП  
- [ ] Без email / без скрина — не в queued, понятная ошибка в UI  
- [ ] Не ломает лимит / batch counters  
- [ ] `harness:check` зелёный  
- [ ] Не автоотправляет письмо

Объём: **S–M (0.5–1.5 дня)**. Блокеров нет — пайплайн кусками уже есть.
