# ИДЕОЛОГИЯ ПРОЕКТА

AVITO CONVERSION BUILDER - это платформа для авитологов поверх Avito API, а не просто редактор текста объявлений.

## 1. Позиционирование
- Продукт: платформа увеличения заявок с объявлений и упрощения работы с Avito API.
- ЦА: авитологи (агентства и фрилансеры).
- Ценность: больше лидов с тем же рекламным бюджетом.

## 2. Главный принцип
Если пользователь видит рост лидов или конверсии, он платит. Если не видит, не платит.

## 3. Продуктовый цикл ценности
Подключил аккаунт или объявление -> увидел просадки -> получил аудит текста и фото -> сделал улучшенную версию -> отправил изменения -> увидел разницу -> повторил.

## 4. Полная логика пользовательского пути
### 4.1 Регистрация
- Вход и регистрация через Яндекс ID.

### 4.2 Onboarding
- Выбор ниши: услуги, недвижимость, авто.
- Выбор цели: больше заявок, дешевле лид, тест объявлений.
- Предложение подключить аккаунт Avito или вставить ссылку на объявление.

### 4.3 Рабочий стол
- Мои объявления.
- Проседающие объявления.
- Аудиты и рекомендации.
- A/B тесты.
- Статистика.
- Кнопка «Подключить Avito» или «Проверить объявление».

### 4.4 Импорт и аудит
- Подключение аккаунта через Avito API.
- Подтягивание объявлений в единый кабинет.
- Подсветка проблемных объявлений.
- Быстрый аудит по ссылке как альтернативный вход.

### 4.5 Создание и улучшение объявления
- Выбор шаблона: максимум заявок, быстрые лиды, премиум услуга.
- Структурированные поля: название услуги, цена, преимущества, опыт, гарантия, описание (опционально).
- Генерация по шаблонам и правилам (без AI-first).
- Ручная доработка: редактирование, порядок блоков, включение/выключение блоков.
- Предпросмотр: как объявление выглядит в Авито.

### 4.6 Визуальный аудит
- Проверка первого фото: продает ли оно в выдаче.
- Проверка наличия инфографики.
- Проверка перегруза текстом.
- Проверка понятности визуального оффера.
- Подсказки по улучшению карточек и изображений.

### 4.7 A/B тестирование
- Что тестируем: заголовок, описание, цена.
- Дополнительно: визуал, первое фото, инфографика.
- Варианты A/B/C.
- Логика: копия объявления -> изменение элементов -> variation.

### 4.8 Публикация
- Бесплатно: ручной экспорт (текст + фото).
- Платно: публикация через API (OAuth/API ключ).

### 4.9 Запуск теста
- Одновременный режим.
- Поочередный режим (рекомендуемый): A 24h -> B 24h -> C 24h.

### 4.10 Данные и аналитика
- Метрики: просмотры, контакты, CTR, конверсия.
- Источник: Avito API.
- Частота: каждые 10-15 минут.
- Вывод: какой вариант лучше по конверсии.
- Авто-рекомендации по правилам и статистике (без AI-first).

### 4.11 Оптимизация и удержание
- Отключение слабых вариантов.
- Фиксация победителя.
- Создание нового теста.
- Удержание: история тестов, динамика метрик, уведомления о просадке.

## 5. Монетизация
### 5.1 Тарифы
- FREE: 1 проект, 1 объявление, ручной экспорт, без API, без A/B.
- BASIC (990 руб): до 10 объявлений, шаблоны, редактор, экспорт.
- PRO (2990 руб): A/B тестинг, до 50 объявлений, аналитика.
- AGENCY (6990 руб): без лимитов, API публикация, мульти-аккаунты, приоритет.

### 5.2 Paywall логика
- FREE не может запускать A/B и подключать API.
- Триггеры апгрейда встроены в пользовательский поток в момент попытки действия.

## 6. Момент ценности
Пользователь должен увидеть конкретную выгоду, например: «Вот какие объявления у вас проседают, вот что в них не так, и вот что дало +40% лидов после правок».

## 7. Отношение к AI
- Без AI-first - это осознанный выбор.
- База продукта работает на шаблонах, правилах и аналитике.
- AI добавляется позже только как ускоритель, а не как ядро ценности.

## 8. Критерии продуктового успеха
- Рост конверсии по тестируемым объявлениям.
- Сокращение стоимости лида.
- Регулярные повторные циклы A/B оптимизации.
- Конверсия FREE -> PRO/AGENCY после подтвержденного value.

## 9. Что мы строим в итоге
Систему для специалистов с быстрым ROI и прозрачной метрикой результата, где ключевая единица успеха - прирост лидов и прибыли, а Avito API работает как двигатель всех ключевых сценариев.

## 10. Локальность и технологическая дисциплина
- Проект ведется только на русском языке: интерфейс, документация, термины задач.
- Приоритет - минимизация внешних зависимостей и простая поддержка.
- Иконки использовать локально (например, lucide в составе проекта), без CDN в продакшене.
- Скрипты и утилиты по возможности хранить локально в репозитории.
- Любой внешний пакет добавляется только при явной пользе и с обоснованием в документации.
