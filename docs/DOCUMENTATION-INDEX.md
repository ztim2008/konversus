## Правило ведения документации

Чтобы документация оставалась живой, дальше стоит соблюдать простой принцип:

1. продуктовые решения фиксировать в `PROJECT-CONCEPT.md`,
2. технические решения фиксировать в `ARCHITECTURE.md`,
3. структуру данных фиксировать в `DOMAIN-MODEL.md`,
4. builder и AI/media слой, **архитектурные повороты** фиксировать в `BUILDER-SYSTEM.md`,
5. block library и смысловые block families фиксировать в `BLOCK-LIBRARY-SCHEMA.md`,
6. interaction schema builder-а фиксировать в `BUILDER-UX-SPEC.md`,
7. текущее состояние проекта обновлять в `PROJECT-STATUS.md`,
8. важные этапы закрывать записью в `CHANGELOG.md`.

## ⚡ Ключевые архитектурные повороты (для нового агента)

> Прочитай это первым делом, если не знаком с историей проекта.

### V3-редактор — единственный стандарт (июнь 2026)

Редактор существует в двух версиях, но **V3 — единственный для новых концептов**.
Подробно: `docs/BUILDER-SYSTEM.md` → раздел «Архитектурный поворот: переход на V3-редактор».

Кратко:
- V3-блоки имеют префикс `doc-` в поле `type`
- V2-блоки — без префикса (legacy, только для старых записей)
- Автодетект версии — в `src/app/dashboard/proposals/[proposalId]/page.tsx`
- Редактор: `src/components/builder/editor-canvas-v3.tsx`
- Управление блоками (↑↓×) — **в левой структурной панели**, не на холсте

### Единый дашборд (июнь 2026)

Нет режимов «Компании» / «Концепты». Один список: компании → внутри каждой её концепты.
Подробно: `docs/BUILDER-SYSTEM.md` → раздел «Архитектурный поворот: единый дашборд».
Файл: `src/app/dashboard/page.tsx`
