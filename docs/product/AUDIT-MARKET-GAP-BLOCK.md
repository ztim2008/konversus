# AUDIT MARKET GAP BLOCK

## Зачем нужен этот блок
Блок “Рыночный gap” нужен, чтобы benchmark был виден прямо внутри экрана аудита, а не жил отдельным кабинетом, до которого пользователь может не дойти.

Он отвечает на вопрос:
не просто что у объявления плохо, а где именно оно проигрывает рынку по городу, услуге и ценовому сегменту.

## Место на экране
Блок должен стоять:
- после карточек score;
- до блока “Топ-3 проблемы”.

Причина простая:
сначала пользователь видит качество объявления, затем сразу понимает его положение относительно рынка, и только после этого переходит к конкретным проблемам.

## Что блок должен дать за 5 секунд
- насколько объявление ниже или выше рыночного эталона;
- по каким 2-3 зонам есть главный разрыв;
- какой первый рыночный разрыв стоит закрыть.

## Структура блока

### 1. Заголовок блока
Содержимое:
- title: `Рыночный gap`;
- subtitle: `Сравнение с похожими объявлениями по городу и услуге`.

Справа:
- badge с контекстом, например `Москва • Ремонт квартир`;
- sample badge, например `Выборка: 18 карточек`.

### 2. Benchmark summary strip
Показываем:
- `benchmark_score`;
- короткий статус: `ниже рынка`, `на уровне рынка`, `выше среднего`;
- summary в одну строку.

Пример:
`Вы ниже рынка по первому фото и конкретности заголовка, но уже на уровне рынка по цене`.

### 3. Gap cards
Показываем 3 основные карточки разрыва:
- Заголовок и оффер.
- Фото.
- Инфографика.

Опционально 4-я карточка:
- Цена.

Каждая карточка содержит:
- название зоны;
- gap score;
- short status;
- 1 ключевую причину;
- 1 краткую рекомендацию.

Пример карточки:
- Зона: `Фото`;
- Gap: `-22`;
- Статус: `ниже рынка`;
- Причина: `Первый кадр слабее рыночного эталона по акценту и читаемости`;
- Действие: `Замените первый кадр на фото с явным объектом и одним продающим акцентом`.

### 4. Рыночные паттерны
Показываем 2-4 коротких паттерна из выборки.

Примеры:
- `У 72% сильных карточек в этой нише есть упрощенная инфографика без перегруза текстом`.
- `В этой категории чаще работают заголовки с конкретной услугой и сроком`.
- `У сильных карточек обычно 6+ фото, у вас 2`.

Этот блок должен усиливать доверие к рекомендациям, а не дублировать их.

### 5. CTA-ряд
Кнопки:
- `Закрыть рыночный gap`;
- `Сформировать улучшенную версию`;
- `Показать похожие объявления`.

Для режима без полного benchmark можно показывать только:
- `Подключить Avito для полного benchmark`.

## Визуальный стиль
Блок должен быть отдельной карточкой внутри audit screen, но визуально чуть сильнее обычных карточек.

Рекомендации по подаче:
- отдельный border-accent по `var(--primary)`;
- компактная summary-полоска;
- 3 gap-карточки в grid;
- без тяжеловесных таблиц;
- без длинных описаний на первом экране.

Важно:
это должен быть продуктовый блок решений, а не аналитическая простыня.

## Состояния блока

### 1. Benchmark ready
Показываем весь блок:
- summary;
- gap cards;
- patterns;
- CTA.

### 2. Benchmark partial
Если есть только внутренний эталон и нет достаточной рыночной выборки:
- показываем summary;
- показываем 1-2 gap cards;
- показываем notice:
  `Пока используем внутренний эталон по нише. Полный benchmark будет доступен после расширения выборки`.

### 3. Benchmark unavailable
Если benchmark еще не рассчитан:
- показываем skeleton или notice;
- CTA: `Запустить benchmark`.

### 4. Direct link mode
Если пользователь вошел только по ссылке:
- показываем benchmark, если данных достаточно;
- под блоком выводим мягкий upgrade:
  `Подключите Avito, чтобы видеть рыночный gap по всем объявлениям и отслеживать изменения после правок`.

## Минимальный data contract для UI
Блок может работать, если backend отдает:
- `benchmark.status`
- `benchmark.scope.city`
- `benchmark.scope.category_name`
- `benchmark.scope.service_name`
- `benchmark.sample_size`
- `benchmark.benchmark_score`
- `benchmark.market_position`
- `benchmark.summary`
- `benchmark.gaps[]`
- `benchmark.patterns[]`

Где `benchmark.gaps[]` содержит:
- `zone`
- `gap_score`
- `gap_direction`
- `title`
- `description`
- `recommendation`

## Что не надо делать
- не прятать benchmark в отдельный раздел;
- не показывать огромный список конкурентов первым экраном;
- не перегружать блок таблицами;
- не писать расплывчатые выводы без конкретной рекомендации;
- не показывать benchmark без контекста города и услуги.

## Критерий качества блока
Пользователь смотрит на блок и за несколько секунд понимает:
- где он проигрывает рынку;
- какой разрыв самый болезненный;
- какое действие закроет этот разрыв первым.

Если блок этого не делает, значит он декоративный и спроектирован неправильно.
