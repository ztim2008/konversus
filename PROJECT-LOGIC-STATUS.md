# Логика проекта и разработки

Этот документ фиксирует единую логику проекта, чтобы не терять фокус и не расползаться по задачам.

## Легенда статусов

- 🟩 Сделано
- 🟨 В работе
- 🟦 Готово к старту
- 🟥 Блокер

## 1) Суть проекта

Factory Proposal Builder — это инструмент для сборки дорогого продающего digital-концепта компании.

Ключевая продуктовая цепочка:

1. Владелец входит в закрытый кабинет.
2. Создает компанию.
3. Создает концепт.
4. Редактирует структуру из блоков.
5. Публикует ссылку.
6. Клиент открывает на телефоне и пересылает дальше.

## 2) Что входит в MVP (жесткие границы)

Входит:

- private dashboard владельца,
- editor блоков концепта,
- share-страница по ссылке,
- мобильный сценарий просмотра и пересылки.

Не входит (до стабилизации MVP):

- сложный командный режим и роли,
- тяжелая CRM-логика,
- избыточная автоматизация AI внутри runtime,
- расширенный PDF-контур как главный сценарий.

## 3) Этапы разработки и статусы

## Этап A — Основа платформы

Статус: 🟩 Сделано

Сделано:

- новый контур на Next.js в текущем репозитории,
- локальная MySQL модель и базовые SQL-скрипты,
- прод-развертывание через PM2,
- базовый auth под single-owner.

## Этап B — Базовый бизнес-контур

Статус: 🟩 Сделано

Сделано:

- сущности компании и концепта,
- создание и хранение proposal,
- share links и счетчик просмотров,
- переход из dashboard в редактор.

## Этап C — Редактор блоков (core)

Статус: 🟩 Сделано для текущего MVP-среза

Сделано:

- структура документа хранится в proposal.structure,
- V2-редактор работает по схеме JSON -> HTML preview в iframe,
- каталог блоков и добавление через компактные карточки с плюсом,
- слои вынесены в выпадающий список с действиями вверх/вниз/дубль/удалить,
- inspector редактирует Hero, факты, текст+фото, фото 100%, видео 100%, галерею, HTML и контакты,
- медиатека открывается модально из конкретных полей,
- ввод текста и смена палитры не сбрасывают позицию preview,
- автосохранение работает с увеличенным лимитом Server Actions.

Осталось после MVP-среза:

- выравнивать визуальное качество каждого нового блока перед добавлением следующего,
- постепенно убрать старые/дублирующие builder-поверхности из интерфейсного контура.

## Этап D — Share-страница (mobile-first)

Статус: 🟨 В работе, основной delivery-сценарий подтвержден

Сделано:

- публичная страница по slug,
- рендер блоков из структуры,
- базовые mobile-share действия (поделиться/скопировать ссылку),
- OG/Twitter мета для пересылки в мессенджеры,
- кнопка обновления share принудительно сохраняет актуальные блоки и палитру перед публикацией,
- PDF оставлен как вторичный download-снимок, не как основной сценарий.

Осталось закрыть:

- довести мобильную читаемость всех блоков,
- выровнять визуальный ритм относительно выбранного прототипа,
- закрепить единый UX пересылки без лишних веток.

## Этап E — Вычистка лишнего и стабилизация

Статус: 🟦 Готово к старту

План:

- удалить/изолировать дублирующиеся или конфликтующие сценарии,
- зафиксировать один основной пользовательский поток,
- унифицировать тексты интерфейса и статусы,
- сократить технический шум в UI и в документации.

## Этап F — Расширение после стабилизации

Статус: 🟦 Готово к старту

План:

- аналитика действий на share-странице,
- углубление медиа-слоя,
- PDF как вторичный экспортный слой (не основной).

## 4) Что сейчас считается "готово"

Функция считается готовой, только если одновременно выполнены условия:

1. Работает в основном пользовательском потоке без ручных обходов.
2. Проверена в production-сборке.
3. Не ломает мобильный сценарий просмотра/пересылки.
4. Понятно описана в этом документе и/или профильной документации.

## 5) Правило работы с приоритетами

Если появляется новая идея, сначала проверяем:

1. Усиливает ли она цепочку "компания -> редактор -> ссылка -> телефонный просмотр".
2. Не размывает ли фокус MVP.
3. Не создает ли второй параллельный сценарий, который увеличивает хаос.

Если ответ "нет" хотя бы на один пункт, задача переносится в отложенный этап.

## 6) Операционный фокус на ближайший цикл

Статус цикла: 🟩 День закрыт, core-UX редактора стабилизирован

Итог дня:

1. Редактор переведен на предсказуемую V2-логику без drag/drop и лишней боковой медиатеки.
2. Добавлены и проверены основные блоки текущего MVP-среза.
3. Убраны критичные UX-сбросы preview при вводе и смене палитры.
4. Share обновляется через явное сохранение актуального draft.
5. PDF закреплен как вторичный формат, фокус остается на share-ссылке.

Фокус следующего цикла:

1. Проверить опубликованную share-страницу как главный клиентский формат на desktop/mobile.
2. Выровнять визуальный ритм share-рендера с iframe-preview.
3. Решить, оставляем ли PDF-кнопку в интерфейсе или прячем ее как вспомогательную.
